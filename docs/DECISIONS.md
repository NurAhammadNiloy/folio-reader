# Decisions

These are implementation decisions and deviations from `PRODUCT_SPEC.md`. Each one gives the reason. Items marked **Needs owner review** are guesses or trade-offs the owner should confirm.

| # | Date | Decision | Reason |
|---|---|---|---|
| D1 | 2026-11-26 | Stack: Vite 8.4, React 19.3, TypeScript 6.0.3, Tailwind 4.3, zustand 5, Dexie 4.4, pdfjs-dist 6.5.438, pdf-lib 1.17, perfect-freehand 1.2, fflate 0.8, zod 4, vite-plugin-pwa 2.0, Vitest 5, Playwright 1.63. Exact versions are in `package-lock.json`. | This matches the plan's suggested stack at current stable versions. TypeScript is held at 6.0.x because typescript-eslint supports `<6.1`. |
| D2 | 2026-11-26 | Node 22 LTS (`.nvmrc`, `engines >=22.12 <23`). | This is what the build container has. Vercel supports 22.x. Moving to Node 24 or 26 is an easy follow-up. |
| D3 | 2026-11-26 | Routes use `HashRouter`. | §12.5 allows hash routes. Direct links and refresh work on static hosting with no rewrites. |
| D4 | 2026-11-26 | UI primitives (Button, Dialog on native `<dialog>`, Menu on the Popover API) are written in-repo instead of with the shadcn/Radix CLI. | This keeps dependencies and bundle size small. Native dialog gives a focus trap and Escape. **The Popover API needs Safari 17+ or iPadOS 17+.** Older iPads are out of scope. Needs owner review if iPadOS 16 matters. |
| D5 | 2026-11-26 | Ink is stored in canonical PDF user-space points, converted only through PDF.js `viewport.convertToPdfPoint` and `convertToViewportPoint`. devicePixelRatio is applied once in the canvas transform. | §12.3. Unit tests prove the roundtrip is within 0.5 units across 6 page geometries, 4 rotations, 4 scales and DPR 1, 2 and 3. |
| D6 | 2026-11-26 | Annotated export draws filled stroke outlines as vectors into a **copy**, using pdf-lib. The original content stream is wrapped in `q … Q`, and an ExtGState alpha (Multiply for the highlighter) is added. Encrypted PDFs are refused with a clear message. | The original stays untouched, and pages are not flattened. Alignment is checked against an independent renderer (Poppler `pdftoppm -cropbox`) to within 2 px. |
| D7 | 2026-11-26 | Notebook PDF export rasterises each page at 2× and embeds PNGs. | It's simple and visually faithful. The trade-off is that typed notebook text is not selectable in the exported PDF. Needs owner review if vector or text export matters. |
| D8 | 2026-11-26 | The eraser removes whole strokes (it doesn't split them). | The plan allows a simple eraser in P0. This keeps undo/redo and persistence exact. The label says "removes whole strokes". |
| D9 | 2026-11-26 | **Restore commits in one IndexedDB transaction** instead of the spec's staged generation pointer. | IndexedDB transactions are atomic. If anything fails (quota, abort, crash before commit), the old library is untouched. That meets the §12.4 goal with less machinery. Everything is validated before the transaction starts: size caps with real expanded-byte counters, safe entry names, per-entry SHA-256, a zod schema and reference checks. The cost is that a very large restore needs enough free quota to briefly hold old and new data. The app checks the estimate first. |
| D10 | 2026-11-26 | Single-writer lease via Web Locks (`folio-library-writer`). Without Web Locks, the tab is **read-only**, not "best effort". | There's no unproven fallback. All current target browsers support Web Locks. |
| D11 | 2026-11-26 | The geometry fixture's page 6 uses a crop box inside its media box. | When a CropBox extends outside the MediaBox, PDF.js and Poppler render it differently: PDF.js uses the intersection. That's a renderer disagreement, not a Folio bug. The fixture stays within the spec's "cropped page" case. |
| D12 | 2026-11-26 | The Unicode fixture (Finnish, Bengali, Arabic, Japanese) is produced by printing HTML through Playwright Chromium. Its text layer is checked as a whole, normalised to NFC. | pdf-lib can't shape complex scripts. Chromium's output splits shaped runs into many spans and emits some odd code points for Bengali (`\u0000`). Text extraction quality depends on the PDF producer, not on Folio. |
| D13 | 2026-11-26 | The encrypted fixture `tests/fixtures/static/encrypted.pdf` (RC4-128, password `folio-test`) is committed. It is generated once with pypdf from Folio's own synthetic single-page fixture. | pdf-lib can't encrypt, and CI shouldn't need Python. The file is synthetic and 2.5 KB. |
| D14 | 2026-11-26 | PDF passwords are kept only in memory while they are being prompted for or used. They are never stored. Folio asks again each time a book is opened. | Privacy. An E2E test checks that the password appears nowhere in IndexedDB. |
| D15 | 2026-11-26 | Resume position is saved **immediately** after paged navigation and debounced by 400 ms during scrolling. It is also flushed on `visibilitychange` and `pagehide`. | A jump followed by a quick reload lost the position. The E2E bookmark test found this. |
| D16 | 2026-11-26 | The notebook link chip shows the **physical page number** ("page 7"). The reader shows the label and the position together ("5 · 7 / 12"). | Notebook links can point to books that aren't open, whose labels aren't loaded. The physical number is never ambiguous. Needs owner review: the chip could show labels later. |
| D17 | 2026-11-26 | Older builds refuse a library written by a newer schema. A native `indexedDB.open` preflight runs **before** Dexie opens. A Dexie `ready` guard is kept as a backstop. | Dexie 4 quietly opens, and even upgrades, a database with a higher version. That would let an older build change newer data (§12.5 "rollback must not silently open an incompatible database"). An E2E test covers it. |
| D18 | 2026-11-26 | Spread and paged views render the neighbouring spread offscreen (`data-prefetch`) inside the render budget. | Page turns are instant, and the canvas cap still holds (6). |
| D19 | 2026-11-26 | The Stage 0 "spike harness" was replaced by the real app plus the unit and E2E suites. The temporary spike route was removed. | The spikes are proven by tests that keep running: geometry, export alignment, IndexedDB Blob storage, PWA precache and the offline E2E test. |
| D20 | 2026-11-26 | The Safari storage-isolation warning is shown in **Settings** when the browser is Safari, not as an install-time prompt. | Browsers don't expose an "about to install" hook on iOS. Needs owner review: a one-time banner on first Safari visit could be added. |
| D21 | 2026-11-26 | No WebKit in the build container. Local E2E runs Chromium only. CI adds a WebKit **smoke** job. | Playwright WebKit can't be installed here. Even when it passes in CI, it is an engine check, not iPad evidence (§12.6). |
| D22 | 2026-11-26 | CSP is `script-src 'self' 'wasm-unsafe-eval'` with no `blob:` workers. `style-src` allows `'unsafe-inline'`. | PDF.js 6 needs WASM for some image decoders. The worker is a same-origin file, so `blob:` isn't needed. Inline styles are needed for the React `style` props used by page geometry and the PDF.js text layer. |
| D23 | 2026-11-26 | Session time is recorded as an estimate (monotonic clock, visible tab only, 120 s idle threshold, 15 s checkpoints). P0 records it but doesn't show it. Activity views are P1 (PRG-02). | §12.6: never claim verified reading time. Recording now means P1 charts will have history. |
| D24 | 2026-11-26 | PDF.js is loaded from its **legacy** (polyfilled) build, aliased in `vite.config.ts`, and the legacy worker. Import errors now include the real cause, and opening a PDF fails after 90 s instead of hanging. | First iPad report: import failed with a generic error. The modern PDF.js 6 build calls `Promise.try`, `Map#getOrInsertComputed` and `Math.sumPrecise`, which iPadOS 17/18 WebKit lacks. Reproduced in Chromium by removing those APIs; the legacy build imports and renders there. Latest Playwright WebKit has them, so CI didn't catch it. |
